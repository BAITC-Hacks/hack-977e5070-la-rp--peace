| Файл | Что это | Когда смотреть |
|---|---|---|

Если источники расходятся:

- состав функций и порядок работы — по `tz_site.md`;
- вид и поведение сайта — по `prototype.html`, экран «Визуал» — по `visual_compare.html`
  (он новее);
- формат данных — по `tz_site.md` §5. `visual_compare.html` ему следует, а заглушки в
  `prototype.html` сделаны в более раннем формате.

## Как работать

1. **Перед задачей** прочитайте в `tz_site.md` разделы §0 (порядок работы), §2 (инварианты
   I1–I7) и §8 (уровни приоритета).
2. **Берите задачу по приоритету.** Сначала P0, потом P1, P2, P3. Следующий уровень
   начинается, только когда выполнены критерии приёмки текущего. Критерий из §8 — это и есть
   «готово».
3. **Инварианты не нарушаются ни на одном уровне.** Особенно I1 (нет вывода без источника) и
   I2 (цитата дословная, проверяется кодом).
4. **Сверяйтесь с макетами в браузере:** `xdg-open docs/spec/prototype.html` и
   `xdg-open docs/spec/visual_compare.html`. Оба самодостаточны; `prototype.html` без сети
   просто покажет системный шрифт вместо IBM Plex. В прототипе можно нажать «Начать анализ»
   без файлов — подставятся демо-документы.
5. **Код макетов не копируйте.** Это ванильный JS с `innerHTML`, написанный для демонстрации.
   Интерфейс собирается на стеке из [`.agents/frontend.md`](../../.agents/frontend.md) §1.

## `prototype.html` — весь сайт

Страницы переключаются через `#` в адресе:

| Страница | Адрес в макете | ТЗ | Приоритет |
|---|---|---|---|
| Загрузка: «Документ До», «Документ После»; внешние документы | `#upload` | §6.1 | P0.1; внешние документы — P3.2, P3.4 |
| Статус обработки, затем автопереход на «Изменения» | `#status` | §6.2 | P0.1 |
| Изменения: сводка, таблица подразделений со штатом, переключатель Word / Визуал | `#changes` | §6.3, §6.4 | P0.8, P0.9; Word — P1.2 |
| Анализ: потеря функций, дублирование, конфликт интересов | `#analysis-loss`, `#analysis-dup`, `#analysis-conflict` | §6.5 | P1.1 |
| Внешние факторы: НПА, другие операторы (с подтверждением найденного) | `#external-npa`, `#external-operators` | §8 P3 | P3.2–P3.4 |
| Чат с готовыми вопросами | `#chat` | §6.6 | P2 |

Поведение, которое нужно сохранить:

- верхнее меню скрыто на загрузке и статусе;
- на «Изменениях», «Анализе» и «Внешних факторах» сверху сводка и «Показать полную
  аналитику» (ТЗ §6 требует её на каждой странице результатов, P1.4);
- у каждой находки есть чипы источников; клик по чипу открывает «Изменения → Word» и
  подсвечивает нужный пункт (ТЗ §6.4);
- стиль: переменные в `:root`, светлая и тёмная тема (`prefers-color-scheme` и
  `data-theme`), шрифты IBM Plex Sans / Mono.

Где прототип отстаёт от ТЗ (делаем по ТЗ):

- «Визуал» в нём — две колонки без карточек и стрелок; вместо него — `visual_compare.html`;
- в «Анализе» нет подстраницы «Пересечение зон» (§6.5, P1.5);
- на карточках анализа нет «Подтвердить / Отклонить» (I6, P1.3) — они есть в панели
  доказательств `visual_compare.html`.

## `visual_compare.html` — экран «Изменения → Визуал»

Встраивается в страницу «Изменения» прототипа вместо её вида «Визуал». Это эталон для P0.8
(ТЗ §6.3):

- сводка: счётчики по типам и «Показать полную аналитику»;
- по каждому блоку три колонки: «до» | карточки изменений | «после»;
- стрелки «до» → карточка → «после», цвет по типу; `also` рисуется пунктиром, потеря —
  «∅ не закреплено»;
- наведение на карточку или пункт подсвечивает всю связку и приглушает остальное;
- клик по карточке открывает панель доказательной базы: вывод → как получен → цепочка
  доказательств (шаги-факты с цитатами, шаги-рассуждения с пометкой «рассуждение агента») →
  что проверено (кандидаты со сходством и порогом) → нормативная база → уверенность →
  «Подтвердить / Отклонить»;
- клик по цитате закрывает панель и подсвечивает пункт;
- цвета типов находок — переменные `--kept`, `--transformed`, `--created`, `--moved`,
  `--loss`, `--duplication`, `--conflict`, `--overlap` в `:root`.

Макет сделан в тёмной теме; фон, шрифты и светлая тема на сайте — из `prototype.html`.

## Демо-данные → фикстура

Фронт работает по фикстуре `fixtures/result.json` (ТЗ §0.3, §5.3), пока нет пайплайна.

- **Находки и блоки** берутся из массива `DATA` в `visual_compare.html`. Поля макета
  называются короче, чем в ТЗ §5:

  | В макете | В `result.json` (ТЗ §5) |
  |---|---|
  | блок `{title, before, after, changes: [объекты]}` | `blocks[]`: `{title, before, after, changes: ["C-001", …]}`; сами изменения — в `findings` по id |
  | пункт `{id, label, st}` | `{id, label, status, clause_id}` |
  | изменение `ev` | `evidence` |
  | шаг `{t, src, inf}` | `{kind: "inference"` если `inf`, иначе `"fact", text, sources}` |
  | источник `s("До"/"После", block, clause, quote, item)` | `{doc: "before"/"after", block, clause_id, clause, quote, item}` |
  | `checked.cands: [[label, clause, score, item]]` | `checked.candidates: [{label, clause, score, item}]` |
  | `conf`, `confNote` | `confidence`, `confidence_note` |
  | глобальный `review[id]` | поле `review` у находки |
  | `compact: true` | не переносится: это вид карточки для `type: "kept"` |

  В макете нет `clause_id` — для фикстуры их нужно назначить (формат `after:dibr:2.8`, ТЗ
  §5.1). Цитаты в макете обрамлены «…»: в фикстуре многоточия убираются, цитата должна
  дословно входить в текст пункта (I2).
- **Word-дифф** (P1.2): формат ответа `GET /api/jobs/{id}/diff` в ТЗ не описан. Единственный
  образец — массив `DIFF` в `prototype.html` (`{block, b, a, moved?, html}` с `<ins>` и
  `<del>`); см. открытый вопрос 3 в ТЗ §10.
- Демо-организация в обоих макетах одна (ДИБиР, ЦЦТ…), но наборы данных отличаются: в
  прототипе больше блоков (Персонал, Закупки, Кадры) и другие формулировки цитат. Это
  вымышленные данные, не документы из `test_data/`.
